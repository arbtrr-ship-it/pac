# PRODUCT_SCENARIOS.md — поведение PAC

Product Architecture Copilot помогает продакт-менеджеру и CPO превращать стратегию квартала в приоритизированный роадмап: продакт описывает инициативу, получает вердикт (Now / Next / Later / Reject) с причинно-следственной цепочкой и видит, как каждое решение влияет на зрелость архитектуры продукта (PAS).

Документ — источник правды для кодового агента. Базовый формат — структурированные сценарии (Триггер → Шаги → Результат → Edge cases → Guardrails). Сверху каждого сценария — JTBD-аннотация «Когда… хочу… чтобы…» как контекст мотивации (зачем продакту этот путь). Сценарии взяты из текущего кода `index.html`; новые фичи реализуются, не ломая описанное поведение.

```
ПУТЬ ПРОДАКТА (4 вкладки)

[Стратегия] ──save──▶ [Гипотеза] ──analyze──▶ [результат] ──add──▶ [Roadmap] ──▶ [AI Office]
  3 шага:               идеи + своя             вердикт              4 колонки      пробелы
  продукт→цель→         инициатива              + 4 скора            Now/Next/      + PAS
  гипотезы                                      + 3 слоя             Later/Reject   + ретро
     │                                                                   │
     └──────────────── PAS (индекс 0–100) обновляется сквозно ──────────┘
```

## Сценарий 1 — Продакт формулирует стратегию квартала

> **JTBD:** Когда продакт начинает новый квартал с размытыми приоритетами, он хочет за 3 шага зафиксировать цель, фокус и ограничения, чтобы дальше оценивать каждую инициативу не «на вкус», а против явной стратегии.

- **Триггер:** продакт открывает вкладку «Стратегия» (стартовый экран) и проходит мастер из 3 шагов.
- **Шаги:**
  1. Продакт вводит название, категорию, описание, ключевую ценность и аудиторию продукта, жмёт «Далее: стратегия».
  2. Продакт выбирает целевую метрику квартала (MRR, Retention 30d и т.д.), baseline и целевое значение, дедлайн, основной и дополнительный фокус, отмечает anti-focus-зоны и задаёт ограничения (стадия, ресурс команды, бюджет, темп, dev-мощность).
  3. Продакт по желанию добавляет стратегические гипотезы-утверждения («Если улучшим онбординг, retention вырастет, потому что…») и жмёт «Сохранить стратегию v1».
- **Результат для пользователя:** продакт сразу попадает на вкладку «Гипотеза», где вверху закреплён контекст-стрип с его целью и фокусом, а ниже — готовые идеи инициатив, подобранные под его фокус и категорию. Версия стратегии сохранена в ретроспективе, индекс PAS начинает считаться.
- **Edge cases:**
  - Продакт оставил пустым название или описание продукта → его не пускают на следующий шаг, всплывает подсказка «Введи название продукта» / «Напиши краткое описание».
  - Продакт обновляет страницу → весь введённый контекст теряется (состояние живёт только в памяти), мастер открывается с шага 1.
- **Guardrails:**
  - Без сохранённой стратегии вкладки «Гипотеза», «Roadmap» и «AI Office» открываются, но работают вхолостую — анализ и генерация идей недоступны.
  - Стратегические гипотезы и anti-focus — опциональны: продакт может сохранить стратегию без них.
  - Каждое сохранение создаёт новую версию (v1, v2…), прежние не перезаписываются — продакт всегда видит историю изменений.

## Сценарий 2 — Продакт анализирует инициативу

> **JTBD:** Когда у продакта появляется идея фичи, он хочет за пару секунд понять, бьётся ли она со стратегией и где у неё слабое звено, чтобы не тратить команду на то, что не двигает целевую метрику.

- **Триггер:** продакт вписывает свою инициативу в поле (или выбирает готовую идею-чип) и жмёт «Проанализировать».
- **Шаги:**
  1. Пока идёт анализ, продакт видит индикатор размышления со сменяющимися подписями («Оцениваю стратегический fit…», «Строю причинную цепочку…»).
  2. PAC оценивает инициативу по 4 параметрам 0–5: Strategic Fit, Impact, Complexity, Confidence — и выносит вердикт по правилам: fit ≥ 4 и complexity ≤ 3 → Now; fit ≥ 3 → Next; fit = 2 → Later; иначе → Reject.
  3. PAC строит причинно-следственную цепочку «инициатива → поведение → промежуточная метрика → целевая метрика» и подсвечивает слабые звенья.
- **Результат для пользователя:** продакт видит бейдж глубины анализа, вердикт, 4 оценки с полосками, три слоя разбора (стратегический с цепочкой и конфликтами, архитектурный с риском перегруза, экономический — LTV/CAC/Cost of Delay) и три варианта реализации (Lean / Experiment / Full). Дальше он может нажать «Добавить в Roadmap».
- **Edge cases:**
  - Продакт жмёт «Проанализировать» с пустым полем → всплывает подсказка «Введи описание инициативы», анализ не запускается.
  - Продакт описал инициативу размыто, без механизма («потому что», «за счёт») и без чисел → Confidence падает, в цепочке появляется слабое звено «не описан механизм влияния» / «нет измеримой метрики».
- **Guardrails:**
  - Без сохранённой стратегии анализ не запускается — продакта просят «Сначала сохрани стратегию».
  - Если инициатива бьёт в anti-focus-зону, её Strategic Fit штрафуется и в стратегическом слое появляется явный конфликт.
  - Причинно-следственная цепочка показывается только для глубины standard/deep — для лёгких инициатив (quick) её нет, чтобы не имитировать ложную глубину.

## Сценарий 3 — Продакт раскладывает роадмап и ловит перегруз

> **JTBD:** Когда у продакта накопилось несколько оценённых инициатив, он хочет разложить их по горизонтам и сразу видеть перекосы, чтобы команда фокусировалась, а не хваталась за всё сразу.

- **Триггер:** продакт жмёт «Добавить в Roadmap» на экране анализа — или перетаскивает карточку между колонками Now / Next / Later / Reject.
- **Шаги:**
  1. Инициатива падает в колонку по своему вердикту, попадает в «Историю решений» и помечается бейджем User или AI и номером версии стратегии.
  2. Продакт перетаскивает карточку в другую колонку, если хочет переопределить приоритет вручную — горизонт инициативы и история обновляются синхронно.
  3. PAC пересчитывает индекс PAS и проверяет распределение по колонкам.
- **Результат для пользователя:** продакт видит наполненный роадмап со счётчиками в каждой колонке, а при 3+ инициативах — «Снимок архитектуры продукта» с долями по колонкам, фокусом и текущим PAS. Историю любой карточки можно открыть кликом.
- **Edge cases:**
  - Продакт набил в колонку «Now» больше 3 инициатив → сверху загорается алерт о перегрузе фокуса и красная точка на вкладке Roadmap.
  - 70%+ всех инициатив скопились в одной колонке → продакт получает предупреждение о стратегическом перекосе.
- **Guardrails:**
  - «Снимок архитектуры» и предупреждения о перекосе появляются только начиная с 3 инициатив — на маленьком роадмапе продакта не дёргают.
  - Перетаскивание меняет только горизонт (zone), но не трогает исходный AI-вердикт инициативы — продакт всегда видит, что советовал PAC изначально.
  - Кнопка «Начать заново» в снимке полностью обнуляет продукт, стратегию, роадмап и историю — это осознанный сброс, а не частичная очистка.

## Сценарий 4 — PAC показывает продакту пробелы в роадмапе

> **JTBD:** Когда продакт уже что-то напланировал, он хочет получить взгляд со стороны на пустые зоны и перекосы, чтобы заметить, что фокус квартала не подкреплён ни одной инициативой.

- **Триггер:** продакт открывает вкладку «AI Office» (генерация запускается автоматически при входе) или жмёт «Пересгенерировать».
- **Шаги:**
  1. PAC раскладывает все инициативы продакта по 5 направлениям AARRR (Acquisition, Activation, Retention, Monetization, Infrastructure) и считает покрытие каждого.
  2. PAC находит пробелы: фокус квартала без единой инициативы, незакрытые направления-«слепые пятна», перегруз Now, перекос в одну зону.
  3. PAC показывает индекс PAS с разбивкой по 5 компонентам и ретроспективу версий стратегии.
- **Результат для пользователя:** продакт видит список системных замечаний от лица PAC — с пометкой важности (❗ Важно / ⚠️ Внимание), причиной и конкретной подсказкой («Рассмотри: push-уведомления, дайджест или streak-механику»), а также текущий индекс зрелости архитектуры.
- **Edge cases:**
  - Продакт зашёл в AI Office без сохранённой стратегии → видит «Сначала сохрани стратегию», замечаний нет.
  - Продакт ещё не добавил ни одной инициативы в роадмап → видит «Инициативы появятся после добавления первой гипотезы».
- **Guardrails:**
  - Зоны, которые продакт сам отметил как anti-focus, не помечаются «слепыми пятнами» — PAC не предлагает усиливать то, от чего команда осознанно отказалась.
  - Если явных пробелов нет, продакт получает честное «✓ Roadmap выглядит сбалансированно», а не выдуманные замечания.

## Сценарий 5 — Продакт возвращается к прошлому решению

> **JTBD:** Когда продакт пересматривает старую инициативу, он хочет увидеть её полный разбор и контекст стратегии на момент оценки, чтобы понять, почему тогда было принято именно такое решение, даже если стратегия с тех пор изменилась.

- **Триггер:** продакт кликает по карточке в роадмапе или по строке в «Истории решений».
- **Шаги:**
  1. Открывается модальное окно с полным текстом инициативы.
  2. Продакт видит вердикт, все 4 оценки с детализацией формулы (focus_match, metric_align, af_penalty, feasibility), причинную цепочку и варианты реализации.
  3. Внизу продакт видит снимок контекста стратегии (продукт, цель, фокус, anti-focus, ресурс, дедлайн), зафиксированный на момент анализа этой инициативы.
- **Результат для пользователя:** продакт получает полную картину решения без повторного анализа и понимает, в каком стратегическом контексте оно принималось.
- **Edge cases:**
  - Продакт успел изменить стратегию (сохранил новую версию) после анализа инициативы → карточка всё равно показывает старый контекст стратегии (v-номер на момент оценки), а не текущий.
  - Карточка без сохранённой причинной цепочки (лёгкий анализ) → блок цепочки в модалке просто не показывается, остальное доступно.
- **Guardrails:**
  - Контекст стратегии в карточке заморожен на момент анализа и не переписывается при смене активной стратегии — это намеренно, чтобы решения оставались воспроизводимыми.
  - Весь текст инициативы и контекста экранируется при выводе — что бы продакт ни ввёл в описание, это не ломает и не подменяет интерфейс.
